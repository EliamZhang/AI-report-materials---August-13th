# PPT 排版优化 Skill

用于优化本仓库 PPT 材料（`AI智能汇报-PPT完整版.md` 及其对应 pptx）的排版与内容表达。遵循 CLAUDE.md 的全部约束（数据不可删改、易编辑优先、细粒度即时确认）。

## 工作流程

1. **先读上下文**：读取目标页面的完整内容及前后页，理解该页在整篇中的定位（是核心页、支撑页还是收尾页）。
2. **识别当前问题**：判断内容是否难读、无视觉层次、信息密度失衡、对比不明显。
3. **给出方案**：涉及取舍（表格形态、删减合并、视觉权重分配）时，用 AskUserQuestion 提供 2~3 个差异明确的选项并附推荐，确认后再执行。
4. **执行并验证**：修改后检查数据是否原样保留、结构是否一致、是否引入格式问题。

## 表格形态决策

- **宽表（一行一笔记录）**：适合"多行同构数据"，如原始银行流水、交易明细、识别结果逐行对应。列 = 字段，行 = 记录。用途：展示加工前后字段对比时，宽表让"新增了哪些列"一目了然。
- **长表（一行一个指标）**：适合"多指标汇总"，如 90 天整体负债、单笔贷款情况。每行是一个不同含义的指标（金额、次数、是/否），没有天然的列方向可展开。
- **判断原则**：有"行对象"就用宽表，有"指标集合"就用长表；不要强行转换。同一页面内宽表/长表错开，形成节奏差。
- 对照两列（如"illion 分类 vs 我方分类"）时，把双方结果并排放在相邻列，左错右对，扫读即得。

## 视觉权重

- **核心内容要占据版面中心/更大面积**：用户说"某部分是核心"时，把它升级为页面主视觉（大图、流程条、对照表），支撑信息下沉。
- 常用手法（按易编辑程度排序）：
  1. 对照表（宽表/长表）——最易编辑，推荐优先；
  2. mermaid 流程图（保留可编辑文本，不用静态图）；
  3. 浅灰底条 + 左侧色条（沿用页面既有样式，如公式条），放大加粗核心文字、用品牌色高亮关键环节；
  4. 避免大量小色块、卡片、标签、装饰线条（CLAUDE.md 易编辑要求）。
- **视觉一致性**：新加的图形元素要沿用页面已有的样式语言（同款底色、同款色条、同款字号体系），不要引入新风格。

## 对比呈现

- **双方对比**（如系统 vs 供应商）：用对称结构——同一对象（顶部/左侧）分叉出两个结果节点，或表格中相邻两列。让"差在哪"一眼可见，而不是读三段文字。
- **"同一个东西，两边识别不同"** 是最直观的对比：一定要保证读者看到的是"同一输入 → 两个结论"，不要各自独立展示。
- 对比结论后附一句话点明差异本质（如"同一条流水，两个结论完全相反"）。

## 模拟数据规范

- **允许模拟**：日期、金额、交易描述等非业务指标类细节可以模拟，但必须：
  - 与素材/真实结论完全一致（笔数、金额、矛盾点、变化位置不能变）；
  - 符合现实场景（如澳洲双周工资几千澳元、Amazon Prime 月费 A$8.99），不出现离谱数值；
  - 在文首/表头标注"模拟示意"，与真实数据区分。
- **禁止模拟**：覆盖率、一致率、样本量、AUC/KS、人工标注效率等业务指标（CLAUDE.md 关键数据不可编造）；此类用【待补充】占位。
- 推导值（如月还款 ≈ A$156×26/12）必须在字段名或括号内标注"估算"及口径。

## 内容易读性

- 段落太长 → 拆为表格/列表；列表太多 → 考虑合并为表格；纯文字对比 → 改左右对照。
- 保留已有数据与结论，只改呈现形式；改写措辞时不得改变含义。
- 模拟流水表格建议列：日期 | 金额 | 方向 | 交易描述 |（对照时加）分类结果列。

## 检查清单（完成后逐项核对）

- [ ] 所有已有数据原样保留，未删减、未改值
- [ ] 模拟数据与结论一致且已标注"模拟"
- [ ] 【待补充】占位未被编造填充
- [ ] 页面内小节编号连续（从 1 开始），标题格式符合 CLAUDE.md 约定
- [ ] 表格/图形与全篇样式语言一致
- [ ] 视觉焦点（用户要求的核心内容）确实突出，支撑信息不喧宾夺主
